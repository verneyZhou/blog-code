5. vue的nextTick实现原理是什么，跟Promise有什么区别？
``` sh
数据变更不会立刻同步改 DOM，而是把“需要更新的组件渲染任务”放进队列，合并去重后在“下一次调度”统一 flush； nextTick 就是把你的回调也塞进同一套 flush 之后的回调队列里，保证执行时机在 DOM 更新之后。

安排 flush”优先用 微任务 ： Promise.then 或 MutationObserver ；再降级到 setImmediate / setTimeout （宏任务）。

- Promise.then ：只保证“当前调用栈结束后，以微任务执行”，不关心 Vue 是否已经把 DOM 更新完。
- nextTick ：保证“Vue 已经把由你这次状态变更引起的渲染队列 flush 完、DOM 已更新”之后执行。
```

// react执行
const Counter = () => {
    const [count, setCount] = useState(0);
    useEffect(() => {
        /**
        挂载       count=0，effect 执行一次 → 创建定时器
          ⚠️ 定时器回调闭包捕获的是【首次渲染】的 count=0
        1s 后      setCount(0+1) = setCount(1) → count=1，UI 渲染为 1
        2s 后      setCount(0+1) = setCount(1) → React 比较 1 === 1（Object.is）
                → 状态相同，直接 bailout，不渲染 → UI 仍是 1
        3s 后      同样 setCount(1) → 继续 bailout → UI 永远是 1
        卸载       clearInterval（仅卸载时执行，因为 effect 只注册了一次）
         */
        const id = setInterval(() => setCount(count+1), 1000);
        return () => clearInterval(id);
    }, []) // 执行一次

    // 优化：
    useEffect(() => {
        // 函数式 setState 的入参由 React 提供最新值，而不是从闭包里读
        const id = setInterval(() => setCount(c => c + 1), 1000);  // c 是 React 给的最新值
        return () => clearInterval(id);
    }, []);   // 定时器只创建一次，不重建

    return <div>{count}</div> // 1
}

const Counter = () => {
